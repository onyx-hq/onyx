# Product Context

Injected into every Claude API call. Its only job: clarify what an agent
**cannot** cheaply retrieve from the code — renamed concepts, confusing
distinctions, product intent for triage, counterintuitive gotchas. **Not** a
feature catalog or changelog. If you'd find it by reading the module, cut it.

---

## Orientation

Oxy (user-facing brand: **Oxygen**) is the operating system for AI transformation:
connect a warehouse and ask questions in chat, where agents write and run SQL.

Deployment modes — almost every bug report depends on which one:
- **Cloud / enterprise** (`oxy serve`, `oxy serve --enterprise`, `oxy start` for a Docker-Postgres dev box) — the real, maintained path: multi-tenant, RBAC, passwordless auth, Stripe billing (`ServeMode::Cloud`). **"Run it locally" means this**, so dev-vs-prod is *not* distinguishable by mode.
- **Legacy single-project** (`oxy serve --local`, `ServeMode::Local`) — one fixed workspace, **no auth**. **Not maintained** — never design behavior around it; when in doubt, assume cloud.

## Terminology & renames (easy to get wrong)

- **Semantic Model** = the thing formerly called **Semantic Layer**. User-facing copy and docs say "semantic model" everywhere (the IDE rail tab, the **New object → Semantic Model** submenu, onboarding). Code keeps the old names: airlayer's `SemanticLayer` type and its `oxy_airlayer_compat` re-exports, the `pages/ide/SemanticLayer/` route module and `/ide/semantic` route, the `semantic_layer` onboarding build phase, `schemas/SemanticLayer.json`, and the Builder's `semantic-layer` reference-card name are all type/wire/storage contracts.
- **Automation** = the thing formerly called **Procedure / Workflow**. Canonical file `.automation.yml` (`.procedure.yml` still accepted); `.workflow.yml` is **no longer a recognized file kind**. Canonical route `/automations/:id`; `/workflows/:id` and `/procedures` are aliases. Rust types keep the `Workflow*`/`Procedure*` names — `type: workflow` and the `agentic_workflow_state` table are wire/storage contracts.
- **Oxygen Factory** = the Developer Portal / IDE (formerly Studio / Oxygen Builder / Oxygen Core). Same `/ide` surface, just the rail label. The **Orchestrator Dashboard** replaced the old **Coordinator** surface.
- **Agentic Agent** (`.agentic.yml`) = Oxy's multi-step FSM agent (two kinds: **analytics** and **app builder**), distinct from the single-shot sense of "agent."
- **Builder Agent** = the file-editing copilot (chat **Build** mode) — distinct from the *app builder* agentic agent.
- **Custom Apps Platform** (code-first React+Vite bundles, shipped with `oxyc publish`) is **not** YAML **Data Apps** (`.app.yml` dashboards). User-facing copy says **"custom app"**, but routes and hosts still say `customer-apps`. Local dev against live cloud data goes through an `oxyc proxy` sidecar (side-effecting function/agent calls held, analytics dropped). Usage analytics are on by default (opt out per build), and the `oxy-` event-name prefix is reserved for platform metrics — an app emitting one gets `400`s.
- **Oxy Functions** = server-side TypeScript handlers declared in `oxy-app.json` and shipped *inside* a Custom App bundle (frontend and backend promote and roll back together) — **not** a YAML Automation task or Data App `task`. Side-effecting powers are **capability-gated in the manifest and fail closed**: `secrets.write`, `email.send` (the platform owns `from`), `storage.read/write` (private per-app silo, presigned URLs only). Isolate gotchas: email templates must be **preact** via `@oxy-hq/sdk/email`; no `Buffer`/`TextEncoder`; `ctx.fetch` decodes as UTF-8, so a binary body needs `encoding: "base64"` or it silently corrupts; an app's **first** `storage.retention` rule changes how uploads are signed, so a non-SDK uploader starts failing opaquely; `ctx.tx()` is **Postgres-only** (others refuse by name rather than emulating), and a `numeric` column must be cast (`amount::text`).
- **`ctx.oltp`** = a **third data plane** — per-org transactional Postgres, not the warehouse and not the semantic model. Each writer (a custom app, or an Airway pipeline landing raw extracts) owns one schema and can't see another's; defaults differ on purpose — a pipeline's `raw_*` schema is analytics-agent-readable, an app's `app_*` schema is private. A slug becomes a schema/role name, so underscores are rejected and an app can't be renamed or deleted while its writer is provisioned. **The two managed planes take opposite stances on who invoked** — `airhouse_managed` mints its credential with the *caller's* workspace role (Owner→Admin, Admin→Writer, Member/Viewer→Reader) and hands every background run Reader, so a **scheduled function cannot write airhouse though a scheduled Automation can**; `ctx.oltp` consults the caller for nothing, writing identically on a schedule and on a route. Reads are unaffected either way, which is why a role problem shows up as "queries fine, writes permission-denied".
- Four similarly-named third-party engines that are easy to confuse: **airlayer** (semantic model), **Airform** (dbt-style modeling), **Airway** (ELT), **Airhouse** (a warehouse + connector).
- **Verified Query** = a plain `.sql` file the analytics agent runs *as-is* when it matches the question, bypassing LLM SQL generation.
- **Two subdomain schemes, easy to confuse** — an **org subdomain** (`<org-slug>.oxygen-hq.com`) boots the whole product pre-scoped to that org's default project, serving its apps under `/a/<slug>/`; a **custom-app subdomain** (`<org>--<slug>.customer-apps.oxygen-hq.com`) serves one app at its own root.

## Roles (the same word means different things at different levels)

- **Platform standing is a grant, not a rank** — a row in `app_admins` carries a **role** (a capability preset) and a **scope** (all orgs, or a list). `is_app_admin` says only *that* someone is staff, so nothing may authorize from it.
- **Global Owner** (`OXY_OWNER` env allow-list → `is_owner`) is root — everything, incl. the Billing queue and Global-admin management. **Global Admin** (`global_admin`, seeded by `OXY_GLOBAL_ADMINS`) is Oxy ops — most of admin + every custom app, but **not** those two.
- **App Operator** (role `app_operator`) — ships and develops custom apps and **nothing else**, optionally scoped to named orgs. An out-of-scope request answers **not found** rather than *not allowed*, so a 404 in an admin surface may be a scope boundary, not a missing row. A grant you issue must be strictly weaker than your own.
- **Partner** (capability-gated, **not** an org membership) — a distributor tier between Oxy staff and tenants: owns downstream orgs and, only for those, creates orgs, manages members, publishes their apps and names each app's audience. **No** general platform reach; every action lands in an append-only per-org audit log.
- **Org Owner / Admin / Member** (`role` in `org_members`) — tenant-internal only, **no** platform reach. Workspace role derives via `EffectiveWorkspaceRole`, so an org Member who is a workspace Admin still reaches Databases / Secrets / Apps / API Keys. Airhouse settings stay open to every member *by design* — the credential it mints is their own, read-only and time-limited.
- **Per-app scope** — a custom app is visible org-wide (default) or restricted to named **org teams**/members, and a **per-app admin** role can extend app-admin rights through a team to someone who isn't org staff. **A grant narrows within an org, never widens into one** — a non-member holding a grant is denied. Only `ctx.user` inside an Oxy Function is **verified** identity — `appRole` is its one gateable field, the browser-side context carries display identity the viewer can edit, and a scheduled run executes as the org owner (so it reads `appRole: admin`, human fields absent).
- **Staff reach is not standing** — staff and partners entering a tenant workspace need an explicit **assume-role session** (60 min, non-renewable, reason logged; `oxyc assume` from the CLI). A staff-facing "you don't have permission" usually means *no active assume session*, not a mis-modeled role.

## Surfaces (for "which component is this?" triage)

- **Home / HQ launcher** (`/`, `/home`) — apps-first landing listing only the **custom apps the viewer can actually open**. **Ask Oxygen** (⌘K) is a right-side drawer. The rail's **Chat** entry was formerly "Threads".
- **Developer Portal / IDE** (`/ide`) — protected `main` auto-redirects edits to a new branch. Semantic surfaces (World Model, explorer, Metric Tree) read the **branch selected in the IDE**, not always `main`.
- **Admin → Workspace Health** — **opt-in per workspace**: no `health_check:` block in `config.yml` — or an unparseable one — means the workspace is never evaluated and is *absent* from the admin table rather than shown healthy. Only an unhealthy *transition* pages Slack, never "degraded". **Anomalies are displayed but do not vote** — severity measures distance past the seasonal band, so a campaign or holiday scores High while nothing is broken; `reconcile.yml` is the correctness dimension, and a workspace without one carries no data-correctness signal.
- **Custom-app health** — a custom-app host answers `200` with the app shell for *every* path, so a monitor on an invented `/health` is green forever; the platform's own endpoint reports `oxy_app_health: pass|fail`, deliberately not `healthy`/`unhealthy` (a `Contains` matcher reads the latter as healthy).
- **World Model Graph** (Globe icon in the rail) — map of the semantic model, driven by `.world-model.yml`. Distinct from the **Context Graph** and the **Metric Tree** — three different graph surfaces. Selecting a measure also sizes **opportunities**; its refusals are deliberate — per-unit rates only (`gap × volume`, never raw totals), significant segments only, no denominator means refused rather than sized — so an empty list is usually right.

## Components worth clarifying

- **Agentic Agent** — when the semantic model lacks a measure it needs, it answers from what exists rather than handing off to the Builder Agent mid-run. It is **freshness-aware** — prompts carry per-source coverage from a view's `meta:` contract, so an answer scoped to "data covers through *date*" is honest, not an under-report.
- **Pre-aggregation** — a **Pre-aggregated** badge means a local Parquet rollup answered instead of the warehouse (stale data under that badge is a freshness bug); every read falls back to the warehouse, so the badge follows the tier that actually answered. The rollups panel lists what was **declared**, not what was built — **Not built** and **Built elsewhere** are statuses, not errors.
- **Airway ELT** (`.airway.yml`) — credentials live in the secret manager, never the YAML; schema migration is **additive only**, so a pipeline on a wrong schema can't self-heal without an explicit **Reset schema**; a retry resumes the same run from its cursor rather than re-pulling history. **One run per pipeline per workspace**, DB-leased on every path (automation steps included), because concurrent runs share one cursor and fold overlapping snapshots into the served table. A busy pipeline makes the next run *wait*; a submit joins the run already queued (ten **Run now** clicks = one run), so a schedule tick that joins is not a failure. `allow_concurrent_runs: true` opts out. Sources declare a **contract** (rows immutable / versioned / opaque, how far back they restate) that a per-source-kind **admission policy** gates on, resolved at *queue* time so a later edit never rewrites past runs. An automation step delegating to a sub-run is capped at **4h** — deliberately under the pipeline lease timeout, so a hung fan-out that normally finishes in seconds sits until that ceiling.
- **Universal Slack Bot** — one shared multi-tenant app (no per-customer installs); Slack users are matched to Oxy users **by email**.
- **Metric Tree & Anomaly Monitoring** — a `.monitor.yml` watches a measure over time (per-segment via `filters`/`group_by`); anomalies land in the **Insights Inbox** with AI root-cause. The separate **Metric Tree** (a Semantic Model IDE tab) decomposes a top-line metric into drivers. Two deliberate silences that read as bugs: scans exclude the current *incomplete* period, and a series isn't scanned until it has **~8 seasonal cycles of history** (≈8 weeks daily), so a new segment stays quiet rather than reporting its ramp. Severity is *distance past the envelope edge* — the same quantity that decided the firing; too few same-phase points means no opinion, floored at **Medium**. Many segments breaching the same bucket group into one **cohort**; a `calendar:` block only *labels* a cohort, never filters. **Explain** compares the same phase one cycle back (Monday vs prior Monday) and scopes to the segment that fired; its drivers sort into explaining / offsetting / **mechanical** (merely tracks its base — neither cause nor offset) / undetermined.
- **Authentication** — passwordless: magic link (AWS SES) plus Google / Okta / GitHub SSO; legacy password auth removed. CI publishes use a long-lived, publish-scoped `OXY_TOKEN` owned by whoever minted it, not a session.

## Counterintuitive gotchas (high-cost, hard to guess)

- **Two ClickHouses, two audiences, two trace-id spaces** — `OXY_OBSERVABILITY_BACKEND` / `OXY_CLICKHOUSE_*` is the *product* store (`oxy-obs-chi`: the tenant-facing Traces console, agent/automation spans only, ids minted by `oxy-observability`); *platform* telemetry is `crates/telemetry` — OpenTelemetry ids on every span and JSON log line of `serve` / `start` / `worker`, exported over OTLP only when `OTEL_EXPORTER_OTLP_ENDPOINT` is set (`otel-logs-chi` → HyperDX). The clusters' collector receives OTLP **traces** but tails **stdout** for logs, so log export stays opt-in (`OTEL_LOGS_EXPORTER=otlp`, off in-cluster) and the stderr JSON is what reaches HyperDX. Each cluster therefore shows **two trace sources**: "Platform Traces" (`otel.otel_traces`, OTel ids, joins to the logs) and "Traces" (`observability_spans`, product ids, joins to nothing else) — a product span and the log line inside it carry *different* trace ids until `oxy-observability` adopts the OTel id (`internal-docs/platform-telemetry.md`). "No traces in HyperDX" is never fixed with `OXY_CLICKHOUSE_URL`, and is usually the wrong source. Dev carries no product traffic — its spans are 100% camera control-plane heartbeats — so request-flow questions have to be asked of prod.
- **DuckDB concurrent init** — two handles opening the same file concurrently have caused SIGSEGV; the pool serializes init, so code opening DuckDB outside it must too.
- **DuckLake has no indexes** — DDL against Airhouse/DuckLake tables must avoid `CREATE INDEX`, `PRIMARY KEY`, and `UNIQUE`; a table carrying one fails and the writer goes inert from there on. Ordering-based predicate pushdown is the substitute, not an index.
- **Observability is ClickHouse-only** — no default in any mode (`--local` included), so unset means capture is simply off, and a removed `duckdb` / `postgres` / `airhouse` label errors at boot and starts *disabled*, reading as "no traces" rather than crashing. Two repeat serving footguns: timestamps must go out as ISO-8601 UTC or the browser mis-parses them (render crash), and trace queries need hard time/size caps — an unbounded scan took the backend offline, not merely timed out. Captured spans surface ~30s later by design.
- **ClickHouse reads everything after `VALUES` / `FORMAT` as row data**, so anything appended to an INSERT gets parsed as a row and the whole insert fails with `Code: 27`: a comment, `ON CONFLICT`, an audit trailer. A host-added trailer once broke every `ctx.warehouse.insert` this way. So a caller never decorates a warehouse statement itself. It hands the statement and its tag to `DatabaseConnector::execute_statement_tagged`, and the connector picks the placement: a trailing comment where that is still SQL, the `log_comment` setting on ClickHouse. `ctx.warehouse.upsert` is refused by name outside Postgres/DuckDB.
- **Empty-result warehouse queries** can panic in the shared Arrow bridge (DuckDB / Snowflake / MotherDuck / connectorx); each path must short-circuit its empty shape. Oversized results hit a cross-connector memory backstop and unbounded semantic/SQL-IDE queries cap at 10k rows — both flag **truncated**, so "missing rows" may be a cap, not a query bug.
- **An external source's own `modified` timestamp can lie** — Toast doesn't advance an order's modified time when a card is captured, so such resources re-read a trailing window every run; a backfill repairing them must widen **both** ends of its range, since the axis it filters on is the untrustworthy one. Relatedly, only **one** component may rotate a QuickBooks refresh token (Intuit voids the old one on every issue, so two rotators deadlock into `invalid_grant` until a manual re-auth) — a read-only `access_token_var` keeps a pipeline out of that role. Such fixes stop *new* bad rows; ones already landed need a one-time cleanup.
- **Workspace file discovery skips by COMPONENT at any depth, and by file NAME separately** — two different rules, and conflating them has split the two enumerations twice. A path is pruned if **any** component is dot-prefixed or is `target` / `node_modules` / `dist` / `build`, so `sub/target/x.view.yml` drops exactly like `target/x.view.yml` (root-prefix-only matching was the first divergence; stray copies under these dirs are the spurious "duplicate view name" error). Separately, a file whose **name** contains `.test.` is a fixture mirroring an entity extension and drops — `orders.test.view.yml` does, while a real `orders.view.yml` under a fixtures **directory** like `v1.test.cases/` does not. Both rules are one definition each, applied by the compile walker and by the working-copy lister, because the IDE reads the second and the stateless fleet reads the first: a file only one of them lists resolves in the IDE and 404s on serve.
- **Two distinct worker concepts, easy to conflate** — the *durable task fleet* (in-process by default, standalone via `oxy worker`) runs queued `TaskSpec` jobs; the *global singleton worker* (`OXY_INPROC_GLOBAL_WORKER`) drives schedules, monitor scans, and pre-aggregation. Toggling one does not affect the other, and with the singleton off **schedule CRUD works but nothing ever fires**. Missed schedule runs collapse to one.
- **Every Builder/analytics/workflow SSE stream must emit a terminal event** (`done` / `error` / `cancelled`) — even when it fails before the orchestrator loop starts (a broken `.view.yml`) — or the frontend hangs forever.
- **Mode-dependent LLM-key check** — any "is a key set?" test must read the **workspace secrets store** in cloud (env vars only in legacy local), and only for the *selected agent's* provider. Home deliberately no longer checks on the common path, so a keyless workspace surfaces on the first failed message — never force-redirect into the wizard over it.
- **Git subdirectory workspaces** — tooling walks up to the real `.git`; branch switching must re-resolve the in-repo subdirectory inside the worktree, or `config.yml` reads as "not found."
- **Production-only "missing workspace/topic" errors are instance affinity, not bad YAML** — anything read per request must come from the compiled workspace in Postgres, not a working copy present only on the owning instance. Symptoms look like content bugs: "Topic not found" with an empty topic list, "failed to read workspace", rejected webhooks, custom-app `origin not allowed`, a pipeline that exists reading as missing. **Not compiled yet** must answer *retryable*, distinct from genuinely-not-found; mid-deploy "workspace directory not found" is transient.
- **Test after pipeline/LLM changes** — **Azure OpenAI** routes through the OSS path (history of agentic incompatibilities). `vendor: openai_compat` demands an explicit `api_url` so EU/GDPR traffic can never silently route to OpenAI, and an `llm.vendor` override outranks the vendor inherited from a referenced model.
- **Input that must be sanitized/allowlisted** — the `http_request` automation task is HTTPS-only and blocks localhost / cloud-metadata / private-IP egress unless a per-task `allow_hosts` opts in. Uploaded custom-app bundles are size-capped **on unpack** — one serve instance hosts many apps.
- **Custom-app subdomains ride a server-side session cookie, separate from main-site client login state** — logout must clear it server-side, and every OAuth provider (not just magic-link) must preserve the return-to-app destination, or the two disagree on whether you're signed in.

## Key file extensions

Most are self-describing; `oxy.yml` under `modeling/<project>/` maps a dbt target to an Oxy connection. Two with semantics you can't guess:

- **`.monitor.yml`** — per-granularity `schedule:`. `timezone` only bites on a `type: datetime` time dimension — a `type: date` business-date column is already a local calendar date, bucketed raw, so `timezone` is inert there. `freshness` (`3d`) means "trust nothing newer than this horizon," so a lagging warehouse's unloaded buckets stop reading as a collapse.
- **`reconcile.yml`** — root-only singleton comparing an Oxy measure against a live external source (Toast), feeding the workspace-health **Reconciliation** dimension. Same `timezone` / `freshness` semantics as `.monitor.yml` — but on a `week`/`month` grain a `freshness` under one full grain buys a settle time that swings with the weekday, so the check reconciles cleanly for days and then reports drift that isn't there.
